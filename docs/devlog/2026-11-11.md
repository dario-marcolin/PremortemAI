## 1. How the settings travel

- One `RunSettings` object per run: provider, LLM key, Tavily key, optional base URL, one model per role (`brief`, `analyst`, `strategist`, `creative`, `validator`, `blueprint`) and the evaluation judge (`eval_judge`).
- The runner puts it in `config["configurable"]["settings"]` next to the `thread_id`. Nodes call `get_llm("<role>")`, which reads it with `get_config()`. Outside a run there are no settings and `get_llm` raises: a node can never fall back to someone else's key.
- LangGraph copies only `str/int/float/bool` configurable values into checkpoint metadata (`get_checkpoint_metadata` in `langgraph.checkpoint.base`), so the settings object and its keys are never checkpointed. A test runs the full graph with marked keys and checks `run.json`, `state.json`, `log.txt`, `blueprint.md` and every checkpoint.
- The Tavily client is built per call from the run's key (the cached global is gone). With no Tavily key the search returns an error as data, the log shows a warning, and the Analyst works from the document.
- The evaluation and the CLI are local tools: they call `RunSettings.from_env(mode="local")`. The app follows `PREMORTEM_MODE`: `local` uses `.env`, `public` (or unset) asks for a key and never reads `LLM_API_KEY`.
- Scripts that call nodes outside the graph (`tests/run_*.py`) use `with using_settings(settings):`.

**Change to note:** the Validator of the pipeline and the evaluation judge are now separate roles. The Validator uses `LLM_MODEL_VALIDATOR` (Sonnet in the anthropic preset); the evaluation judge uses `LLM_JUDGE_MODEL` (Haiku in the preset).

**`.env` rule:** `LLM_MODEL`, when set, replaces the model of every role, the blueprint included. Leave it empty to get the preset (Opus for the blueprint). Use `LLM_MODEL_<ROLE>` to change one role.

## 4. Demo run on the gemini preset

Dario ran the CLI with a free Gemini key. Two problems came up before the run worked:

1. **Wrong models.** `LLM_PROVIDER=gemini` was set, but the old `LLM_MODEL=anthropic:claude-haiku-5-5` in `.env` replaced every role, so the Gemini key was sent to Anthropic (401). Fix: `from_env()` now stops with a message that names the variable to empty (`The 'gemini' preset uses google_genai: models, but LLM_MODEL=anthropic:…`).
2. **New key format.** Google AI Studio now also issues keys that start with `AQ.`, not `AIza`. `detect_provider` recognises both.

Then `check_model` hung: `gemini-3.8-flash` answered `504 DEADLINE_EXCEEDED` after 58 s and again after 88 s, and the client retried each time. `gemini-3.5-flash-lite` answered in 3 s, `gemini-3.6-flash` in 6 s. Fixes: the blueprint of the gemini preset uses 3.6 Flash; every request has a timeout; a 504 is explained as "The model did not answer in time".
