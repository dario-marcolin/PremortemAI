## 2. Phase 1 – Schemas and state (PR #1)

Branch: `phase-1/schemas-state`

### Design decisions

1. **Node map.** The graph follows the roadmap diagram: ingestion → Analyst (ReAct subgraph) → Validator (analysis) → Strategist ⇄ Validator (strategy) → human approval → Creative ⇄ Validator (campaign) → Launch Blueprint.
2. **Ids.** Sources are numbered `S1, S2, ...` in a single sequence across the document and the web, in the order they are found. Segments are `SEG1, SEG2, ...`. Both formats are enforced with a regex in the Pydantic models, so a wrong id fails validation.
3. **Severity of validation issues.**
   - `blocking`: `passed=False`; the stage is revised with the issues as feedback, up to `MAX_REVISIONS = 2`. After that, the graph moves on and the unresolved issues are shown at human approval and in the blueprint.
   - `warning`: `passed` stays `True`; the issue is only reported.
4. **Estimated fields.**
   - `Competitor.price_level` is one of `low | mid | high | premium | unknown`.
   - `MarketSegment.estimated_size` is free text (e.g. "~2M households, S3"), left null unless a source states it, and flagged in `data_quality_notes`.

### Files

- `premortem/schemas.py`: `CompanyBrief`, `Source`, `Competitor`, `MarketSegment`, `Analysis`, `Strategy`, `CampaignMessage`, `Campaign`, `ValidationIssue`, `ValidationResult`. Every field has a `Field(description=...)`, written as an instruction, because the LLM reads these descriptions when producing structured output. `ValidationResult.blocking_issues` returns only the blocking issues, for the routing functions of Phase 8.
- `premortem/state.py`: `LaunchState` and `AnalystState(MessagesState)`.
- `tests/fixtures/dummy_state.json`: one complete, hand-written `LaunchState` ("BrewBox", a coffee subscription in Italy), with one strategy revision and one campaign warning. Reusable in later tests.
- `tests/test_schemas.py`: builds every model from the fixture, checks that every cited source and segment exists, and checks that wrong ids are rejected.

### Alignment with the roadmap

A first version used different field names. It was compared with the roadmap and corrected:

| Model | Before | Now |
|---|---|---|
| `CompanyBrief` | `company`, `product` | `company_name`, `company_description`, `product_name`, `product_description` |
| `MarketSegment.estimated_size` | string, "unknown" if missing | `str \| None` |
| `Strategy` | `positioning` | `positioning_statement` |
| `CampaignMessage` | `message`, `audience_need` | `channel`, `headline`, `body` (`channel` is needed by the Phase 7 rule "every message channel is in `strategy.channels`") |
| `ValidationIssue` | `field` | `check` (name of the check that raised it) |
| `ValidationResult.stage` | included `brief` | `analysis`, `strategy`, `campaign` only |
| `LaunchState` | optional keys | `X \| None` fields, as in the roadmap |

### To confirm in the PR review

Two choices differ from the roadmap sketch:

- `price_level` is a fixed list of values instead of `str | None`.
- `validations` uses an `operator.add` reducer: validator nodes return `{"validations": [result]}` and the full history is kept automatically.

## 3. Phase 2 – Ingestion (PR #2)

Branch: `phase-2/ingestion` (based on `phase-1/schemas-state`)

### Demo document (review: C)

- Fictional company **Verdo Foods** (Bologna, 28 employees, 4.2 M€ turnover) launching **Proteo Crisps**, plant-based protein crisps, in **France** in March 2026.
- 3 pages: company, product, goals, market figures, consumer groups, competitors (Barebells, Gerblé, private labels), production and distribution, open points. All figures cite a source (fictional, and declared as such in the document).
- **Left out on purpose** to test `missing_info`: the product price and the marketing budget.
- **Trap for the evaluation:** vegans have the highest purchase intent (72%) but are only 1.3 M adults (2.5%). Weekly sport practitioners are 17.5 M (34%) with 41% intent. The document says the founders lean towards vegans.
- `data/demo/demo_company.pdf` and `.docx` are **generated** by `scripts/build_demo_docs.py`. To change the content, edit the script and run `uv run python scripts/build_demo_docs.py`. The script also generates the parser fixtures `tests/fixtures/sample.pdf` and `sample.docx`.
- New dev dependencies: `python-docx`, `fpdf2` (only used by this script and the tests).

### Parser (review: C)

`premortem/ingestion/parser.py` – `parse_document(path) -> str` with MarkItDown.

- Only `.pdf`, `.docx`, `.pptx`, `.md`, `.txt`; anything else raises `DocumentParseError` listing the allowed types.
- Clear errors for a missing file, an empty file, and a PDF with no text layer (e.g. a scanned PDF; OCR is not supported).
- Tokens are estimated as characters / 4. Above `DOC_TOKEN_BUDGET` the text is truncated and a warning is raised.
- `tests/test_parser.py`: 11 tests (both fixtures, .md/.txt, wrong extensions, missing, empty, scanned, corrupted, truncation).

**Problems found and fixed**

1. *Corrupted files were accepted.* When MarkItDown cannot read a PDF, it silently falls back to reading the raw bytes as text. The parser now checks the file signature first (`%PDF` for PDF, `PK` for DOCX/PPTX, which are zip files).
2. *PDF tables lose their row structure.* MarkItDown extracts PDF tables column by column, so the link between "vegans" and "2.5%" can be lost. Each table in the demo document is now followed by a short prose summary of its figures. DOCX tables are extracted correctly as Markdown tables.

### Brief extractor (review: B)

- `premortem/prompts/brief_extractor.md`: extract only what is stated, never invent, use the document's own figures, fill `missing_info` with what a launch plan needs but the document does not give (checklist: price, marketing budget, target group, channels, launch date, competitor prices).
- `premortem/prompts/__init__.py`: `load_prompt(name)` reads `premortem/prompts/<name>.md`.
- `premortem/ingestion/brief_extractor.py`: `extract_brief(text) -> CompanyBrief` with `llm.with_structured_output(CompanyBrief)`.

**Result on the demo PDF (checked by hand):** every field matches the document; `price_hint` is `null`; price and marketing budget are in `missing_info`; competitors and the four goals are correct.

**Open point for B:** Haiku sometimes still lists the launch date in `missing_info` (reworded as "campaign timing"), although the document states March 2026. The prompt was tightened once; it is now borderline rather than wrong.

### Change to Phase 0 code

Claude 5 models reject the `temperature` parameter (API error 400). `get_llm()` in `premortem/llm.py` now sends `temperature` only when it is set. It can be set with the optional `LLM_TEMPERATURE` variable in `.env` (added to `.env.example`), for providers that accept it.

### Manual end-to-end run

`tests/run_e2e_up_to_phase2.py` runs the whole chain: document → parser → brief extractor.

```bash
uv run python tests/run_e2e_up_to_phase2.py                        # demo document
uv run python tests/run_e2e_up_to_phase2.py --doc path/to/file.pdf
```

Each run creates `outputs/e2e_phase2/<timestamp>_<document name>/` with `document_text.md` (what the LLM receives), `brief.json` and `run.json` (document, model, tokens, duration, parser warnings). `outputs/` is git-ignored. The file has no `test_` prefix on purpose, so `pytest` does not run it and does not spend API credits.
