# Evaluation report (Phase 14)

Research question: *can coordinated specialized agents produce a launch plan that is more coherent, traceable and reusable than isolated AI prompts?*

Updated 2026-11-11 12:50. The agents and the single prompt use `anthropic:claude-sonnet-5-5`, `anthropic:claude-opus-5-5` for the blueprint summary, on the same document; the metrics use the judge `anthropic:claude-haiku-5-5`, 3 runs per plan (mean, min–max in brackets). The multi-agent pipeline runs with auto-approve. Generated by `eval/run_eval.py` from `eval/results.json`.

## Method and limits

- **Traceability.** The judge extracts the factual claims about market, competitors, customers and segments (not the company's facts about itself). A claim counts only if its quote is in the plan, and a reference only if it is cited on the same line. Valid source: the company document, or a URL that exists (a page that refuses bots still counts; a 404 or an unknown domain does not).
- **Faithfulness.** Each figure of those claims is searched in code in the document and in the pages of the cited URLs, with rounding ("1.3 million" matches 1,276,000). *Unverifiable*: a cited page could not be read; these figures are left out of the score. Figures the plan computed (ratios) are not checked.
- **Coherence and trap.** One judge call with a fixed rubric (`eval/prompts/coherence.md`). The judge does not see the validation log. It is a cheaper model than the pipeline's Validator (professor's notes), and the same judge scores every system and every preset.
- **Judge spread.** The judge scores each plan several times; the tables give the mean and, in brackets, the lowest and highest run. A gap between the systems smaller than this spread is a tie.
- **Cost and latency.** Tokens and seconds of the system itself (pipeline time, human wait excluded); the evaluation's own judge calls are not counted.
- Small sample (one pipeline run per case and system): read the per-case table, not only the averages.
